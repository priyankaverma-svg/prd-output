# Release Doc — Review Checklist

Run before delivering final output.

## Structure
- [ ] All section labels match `references/release-doc-template.md` exactly
- [ ] Business unit, owners, release date, and PRD link filled (or TBD flagged)
- [ ] TBD used only where genuinely unknown — each TBD called out to user

## Content quality
- [ ] What it Is — plain English, no deploy mechanics
- [ ] Why it Matters — problem/cost of status quo, no solution jargon
- [ ] Key Benefits — concrete outcomes, no invented metrics
- [ ] NSMs Impacted — named metrics only; no assumed direction of impact
- [ ] No invented numbers, dates, owners, or dollar figures

## Voice
- [ ] Professional, plain language — exec and new hire can follow
- [ ] Acronyms spelled out on first use
- [ ] Max one technical term per sentence in narrative sections
- [ ] Any pasted result tables reproduced with exact figures

## Handoff
- [ ] Doc title and URL ready for `@release-notes` if user wants a slot next
